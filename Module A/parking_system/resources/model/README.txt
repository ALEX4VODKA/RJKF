Blender 3D 模型导出说明（实时 3D 模式用）
==========================================

界面中间那一整块 3D 区域由 three.js 实时渲染，模型来自这里导出的
`resources/model/parking.glb`。没有这个文件时，viewer 会自动搭一个
演示场景（立柱 + 闸杆），所以随时可以先跑界面。

------------------------------------------------------------------
零、当前模型状态（2026-10 实测）
------------------------------------------------------------------
parking.glb            124.8 MB
动画 4 段              gate_in_open / gate_in_close /
                       gate_out_open / gate_out_close   ✅ 命名正确
每段时长               10 s（整条时间轴）→ 播放时自动压到 1.8 s
摄像机                 无 → 按 gate_in / gate_out 节点自动取景
节点                   gate_in, gate_out, lu, mentin, zhu1, zhu2

也就是说：现在打开程序就是这台模型，能正常抬杆 / 落杆，
只是体积偏大、构图是自动算的。下面第 5、6 节是优化方向。

------------------------------------------------------------------
一、导出步骤
------------------------------------------------------------------
1. File → Export → glTF 2.0 (.glb)
2. 勾选：
   ☑ Include → Selected Objects（只导要用的部分，别把整个场景塞进去）
   ☑ Data → Apply Modifiers
   ☑ Data → Cameras（如果要用相机作为机位）
   ☑ Animation → Animation
   ☑ Transform → +Y Up（默认就是，不要改）
3. 文件名填 `parking.glb`，存到 `resources/model/` 下

建议：先删掉不相关的物体（天空球、灯光阵列、摄像机轨道等），
只留出入口建筑、两个道闸、车辆模型。

------------------------------------------------------------------
二、动画命名（必须一致）
------------------------------------------------------------------
每个动作导出成一段动画片段，名字必须严格是：

    gate_in_open      入口抬杆
    gate_in_close     入口落杆
    gate_out_open     出口抬杆
    gate_out_close    出口落杆

Blender 里的做法：
  · 用 Action 管理动画，把 Action 直接重命名成上面的名字；
  · 或者用 NLA，把 Strip 命名成上面的名字（导出时按 strip 名生成动画）。

名字不对不会报错，但动画不会播放——viewer 只在名字匹配时才把它挂到对应道闸上。

时长不用刻意裁：viewer 会按 `clip.duration / 1.8s` 自动压缩播放速度，
10 秒的动画也能在 1.8 秒内播完（真实道闸本来也就 1.5~2 秒）。

------------------------------------------------------------------
三、机位（可选，但建议加）
------------------------------------------------------------------
在场景里放三台摄像机，命名：

    cam_in      入口道闸的摄像机位
    cam_out     出口道闸的摄像机位
    cam_wide    全景机位（空闲时的画面）

trigger 的时候，镜头会从当前位置飞到 cam_in / cam_out，
再播对应动画——这就是「镜头归位」。

  · 放摄像机：机位和朝向都照搬；
  · 放空物体（Empty）：只取位置，朝向自动看向场景中心；
  · 不放：按 gate_in / gate_out 节点自动生成四分之三侧机位（当前就是这样）。

画面越窄，镜头会自动后退得越远，保证道闸完整入镜。

------------------------------------------------------------------
四、画面建议
------------------------------------------------------------------
· 背景：不用导出天空球，viewer 会铺浅灰背景 + 地面；
· 灯光：一两盏主光 + 环境光即可，太多会让 3D 和界面风格不一致；
· 材质：glTF 只带 PBR 基础参数，复杂节点材质（程序纹理、SSS）不会导出；
· 面数：单机演示 20 万面以内很轻松，超出注意显存。

------------------------------------------------------------------
五、放好之后
------------------------------------------------------------------
1. 把 parking.glb 放进 resources/model/；
2. 重启程序（或点 3D 卡片右上角 ⟳ 重新加载）；
3. 卡片右上角应显示「实时 3D」；如果显示「实时 3D · 演示模型」，
   说明 glb 没被读到，检查路径和文件名。

如果 3D 起不来（没装 WebEngine、显卡/驱动问题），程序会在 10 秒内
自动降级到视频 / 序列帧 / 占位画面，不会卡死。

------------------------------------------------------------------
六、体积优化（当前 125 MB 偏大）
------------------------------------------------------------------
1. 删掉用不到的物体（车辆、行人、装饰、隐藏图层）；
2. 贴图压到 1024 或更小，能合并的合并成一张图集；
3. 导出时勾选 Draco 压缩（three.js 侧已带 GLTFLoader，需要再加 DRACOLoader）；
4. 目标：10–20 MB，首次加载 1 秒内。
